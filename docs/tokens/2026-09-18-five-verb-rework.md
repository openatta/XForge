# 五命令改造 · token 消耗账（2026-09-18）

> 一次改造实际花掉的 tokens：从需求提出、分析、实施，到跑 live 之前为止。
> 数字是从会话转录逐条 API 调用累加出来的，不是估算。
> 目录约定：`docs/tokens/` 一次改造一份，文件名 `<日期>-<改造名>.md`。

## 1. 口径

| 项 | 值 |
| --- | --- |
| 数据源 | `~/.claude/projects/<slug>/<session>.jsonl`（会话主转录）+ 它派出的 **4 个子 Agent** 转录 `<session>/subagents/*.jsonl` |
| 去重 | 按 `message.id` 归并：流式写入会把同一条回复落成多条记录，取**最后**一条（usage 随流累加，末条才是完整的） |
| 窗口 | 2026-09-18 18:23:14 → 19:59:19（本地 UTC+8），**1 小时 36 分** |
| 窗口起点 | 需求第一句「当前版本仅支持 claude agent 开发工具，现在想支持 codex…」 |
| 窗口终点 | 第一次 `npm run test:live` 启动的那一刻（live 实跑本身在窗口外，见 §5） |
| 模型 | 转录里每条 usage 报的都是 `deepseek-flash`（本机 `ANTHROPIC_BASE_URL` 指向 deepseek 网关），不是 Claude |
| 缺的一块 | 窗口内 **6 次上下文压缩**（18:58 / 19:06 / 19:14 / 19:24 / 19:39 / 19:55）本身也是模型调用，转录里不落 usage —— 所以下面的数是**下限** |

口径说明：`input` 是**未命中缓存**的输入；`cache_read` 是每次都从缓存重读的对话前缀（同一个前缀会被反复计入）；`cache_creation` 是写入缓存的量。四者相加即"计费口径总计"。本仓库不折算费用，只报 tokens。

## 3. 几个能看出门道的地方

- **`cache_read` 占 98.2%，`output` 只占 0.65%**。每次调用都要把整段对话前缀从缓存重读一遍，而上下文从 10,148 涨到峰值 **167,084** —— cache_read 随轮数近似平方增长，它的量级反映的是"会话有多长、调了多少次"，不是"写了多少字"。
- 真正新生成的量是 **output 457k**；真正未命中缓存的新输入是 **input 814k**。
- 单次调用的上下文：最小 10,148（18:23 起步）· 中位 111,809 · 75 分位 140,191 · 最大 167,084（19:38）· 窗口最后一次 130,252。
- 平均每次调用：input 1,230 / output 690 / cache_read 104,867。
- 按小时：18 点 129 次调用（input 328,243 / output 117,261 / cache_read 9,606,144）；19 点 533 次（input 485,781 / output 339,838 / cache_read 59,815,936）。拐点在 P3。
- `cache_creation` 全程为 0 是网关的口径（deepseek 侧只报读不报写）；换 Anthropic 直连这个拆分大概率不是这样，别把这一行当产品结论。

## 4. 怎么复算

`recount.mjs` 就在这个目录里，是上面这张表的算法（按 `message.id` 归并、末条为准；同时收子 Agent 转录）：

```sh
S=~/.claude/projects/<slug>/<session>
node docs/tokens/recount.mjs "$S.jsonl" "$S/subagents" \
  --phase "窗口内=2026-09-18T10:23:04Z/2026-09-18T11:59:19Z" \
  --phase "P5 live 实跑=2026-09-18T11:59:19Z"
```

跑出来第一行就是 §2 的合计（662 次 / 70,693,203）。段边界换一组就得到 §2 的分段表；不给 `--phase` 则打总量与按小时分布。

## 5. 窗口外：live 实跑（对照，不是上面那笔账的一部分）

两件事经常被混为一谈，分开记：

- **编排开销**（驱动 live 的开销）：窗口结束后 112 次调用，input 62,054 / output 64,066 / cache_read 13,285,376（写到这份账时的快照，20:28；之后还在增长，因为写这份文档本身也算在里面）。

## 6. 这份账不含什么

- 窗口内 **6 次上下文压缩**的用量（转录不落 usage）—— 真实总量高于表中数字。
- 别的会话。同日 08:35–13:35 那场 npm 发布是另一个会话，没算进来。
- 任何费用换算：本仓库只报 tokens。
