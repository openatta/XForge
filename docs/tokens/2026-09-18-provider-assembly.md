## 口径

- **数据来源**：Claude Code 本次会话的转录（`~/.claude/projects/<项目>/db878d8f-….jsonl`），
  逐条读模型返回里的 `usage`，按时间戳落进阶段区间。阶段边界取**提交时间**与**用户消息时间**，
  所以每一段是「这段时间里为这件事花掉的」，不是事后估算。
- **四个字段**：`output` 是模型生成的（回答、思考、写进文件的内容）；`cache_read` 是命中提示缓存的输入；
  `cache_write` 是写入缓存的输入；`新输入` 是两者都没命中的输入。
- **`cache_read` 为什么这么大**：长会话里同一份上下文会被后续每一次调用重新读到。
  296 次调用平均每次读约 24 万 token，就累成了几千万。它按缓存读计价（远低于新输入），
  **不能和 `output` 直接相加当作「总消耗」**。
- **只算主会话**：本次没有派任何子 Agent，没有别处的隐藏开销。
- **不折算费用**，与 live 测试的计分口径一致（live-test 设计 D6：只报 tokens）。
- 数据截至 `2026-09-18T12:30:51Z`（写这份文件的时刻）。最后一段「答疑与本文件」天然还在增长。
