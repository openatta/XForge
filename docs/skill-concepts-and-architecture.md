# XForge Skill：概念与架构

> 共同概念、对象与不变量在 [概念与架构](concepts-and-architecture.md)。
> 这份只讲 **Skill 这一层**：该装什么、不该装什么、它们之间怎么组织、上下文在哪里被切断。
> 不含 Skill 正文、不含迁移方案。
>
> 主文档持有的东西这里不复述，只引用名字。

---

## 0. Skill 是哪一层

两条边界夹出了它：控制面**不做判断**（主文档《定位》），而它**能陈述事实**。

> **控制面能陈述的事实，Skill 说「按它执行」；控制面判不了的取舍，Skill 来判。**

Skill 不是命令行的说明书，不是流程定义的副本，也不是事故档案 ——
那三样各有归宿，而且都不在这里（事故档案的归宿是诊断码字典）。

---

## 1. 总则：Skill 的厚度与控制面的完整度成反比

一条 Skill 里的禁令（「不要打开那个文件」「不要再读一遍」）从来不是免费的纪律，
它是一张**控制面欠费的账单**。

主文档的 `名字不单飞` 与 `切片自称完整` 这两条，存在的目的不是让回复更礼貌，
是让 Skill 里那条对应的禁令**没有必要写**。

由此得到写 Skill 时最该反复问的一句话：

> **每当你想写下一条禁令，先问它是不是控制面的一个缺口。**
> 是，就去补控制面；不是，才写进 Skill。

一条与便利作对的指令会输。移除诱因，不要把禁令说得更重。

## 2. 两种 Skill

### 2.1 入口 Skill —— 用户唯一需要记住的名字

它自己不做任何一站的工作，只做三件事：

1. 跑「读」，拿到当前在哪一站
2. 按控制面报的结果，把那一站交给该去的地方执行
3. 收回一份极短的回报，再跑一次「读」取真相

**它是全局一致的东西的唯一落点**：调用骨架只在这里写一次，不在每一站的 Skill 里重复六遍。

### 2.2 站 Skill —— 每站一个

承载那一站的判断。它不重述调用骨架，不重述控制面会给它的事实。

### 2.3 路由表不在入口 Skill 的正文里

入口 Skill 里**不许出现任何一张「哪一站对应哪个 Skill」的表**。
那张表是流程定义的内容，控制面读它、在「读」的回复里报出来 —— 入口按报出来的走。

手抄一份路由表，就制造了一个改流程定义时会静默失效的副本。
这同时意味着控制面的「读」必须在回复里带上**本站的 Skill 名**（主文档《加载三级》第 1 级已列入）。

## 3. 上下文隔离

### 3.1 问题的正确表述

主文档《一个 Change 的骨架》把 Stage 之间的传递方式写死了：产出是文件，其余都是草稿。
会话上下文是一条**架构从未承认过的第二通道**。它把调查过程、失败重试、被取代的旧回复
一并带到下一站，而且只增不减。

隔离本身不是新概念 —— 加载三级的第 2 级里已经写着「其它实现方案的任何东西」，
并且说明那不只是省 token（`规格侧共享` 之下，那是「独立」这个词的全部含义）。
**把同一条规则从方案之间用到站之间，是一致的延伸，不是新增的机制。**

### 3.2 冷启动是一次免费检验

一站能不能从零上下文开始干活，就是对**上一站的产出是否自足**的一次检验。

跑不动，说明某份产出或某份台账欠写了。那是个真问题 ——
今天它被会话记忆盖住了，而被盖住正是它没被发现的原因。

返工同理：一站被打回来，它靠的是台账里那条带着返工去向的条目。
台账写对了，冷启动就够；写不对，问题暴露在它该暴露的地方。

### 3.3 三个概念必须分开：继承、交接、冷启动

| | 是什么 | 后果 |
| --- | --- | --- |
| **继承** | 执行者拿到主会话的**全部对话历史** | 拿到的正是要甩掉的那堆累积 —— **与隔离互斥** |
| **交接** | 主会话把一份**写好的简报**当作执行者的输入 | 执行者只拿到交出去的那些，边界由交的人画 |
| **冷启动** | 什么都不给，执行者自己去问控制面 | 多付一次定向 |

**执行者从零开始组建自己的上下文。** 它的系统提示是它自己的，它看不到主会话说过什么。
所以这套设计要的是**交接**，不是继承 —— 有些运行时提供「完整继承父上下文」的派生方式，
那恰好是反面：它把累积原样复制一份，还多花一次派生。

由此得到一条对简报的硬要求：

> **开局时，简报就是执行者知道的一切。**

「开局时」这三个字不能省：执行者随后照样可以调用控制面去要更多（§3.4 末）。
硬要求约束的是**交出去的那一份必须自足**，不是禁止它再取。

**还有一样东西不在磁盘上**：本次会话里用户说过的话 ——
「这个先做快一点」「先别动那个模块」。它既不是产出也不是台账，冷启动的执行者看不到。
所以简报里必须有一格装它，由入口负责带过去。

并且它自带一条判据：**一条用户指示如果重要到每一站都要遵守，它就不该只活在会话里** ——
那样的指示属于项目的本地化区（长期的）或提案（这次改动的）。会话那一格只装真正临时的。

### 3.4 入口预加载**定向**，执行者承担**材料**

这是隔离能省下东西的关键，也是最容易做反的地方。
「定向」与「材料」的定义在主文档《定向与材料》—— **定向 = 0 级 + 1 级，材料 = 2 级**。

| | 谁保有 | 累积量 |
| --- | --- | --- |
| **定向** | **入口预加载，转交给执行者** | 每站一份，小 —— 这一级的设计目标就是便宜 |
| **材料** | **执行者自己点名取**，用完随上下文一起丢掉 | 大，但**不回流** |
| **过程**（调查、试错、被取代的中间结果） | 执行者，**丢掉** | 大，且今天全部在累积 |

所以「主 Skill 把必要的加载先加载好」要精确到这一句：

> **入口预加载的是定向，不是材料。**

入口替执行者付掉第一次定向，省掉一次冷读；但它**不替执行者读任何正文** ——
一旦入口开始预取材料，它自己就变成了新的累积点，隔离就白做了。

两边各自的累积量：**入口** = 站数 × （一份定向 + 三行回报），有界；
**执行者** = 这一站的全部工作，无界但用完即弃。

**预加载不等于禁止执行者调用控制面。** 它照样要跑「进」和「证」，写完一份产出也该重新「读」
一次看自己还欠什么。省掉的只是**开局那一次冷定向**。

**而且预加载是优化，不是契约：**

> **站 Skill 必须能自己定向。** 收到简报就用，没收到就自己跑一次「读」。

这一条守住了，三种用法才都成立：入口编排、用户直接调用某一站、宿主不具备隔离能力。
站 Skill 一旦依赖「有人先喂我」，老的逐站调用方式就断了。

### 3.5 简报按稳定度排序，不按重要度排序

缓存的机械原理与「顺序不等于分级」在主文档《定向与材料》。这一层要定的是**简报的段落**：

| 段 | 内容 | 对应 |
| --- | --- | --- |
| **① 项目不变量** | 治理开关、模块、路径、判定图、索引域层、章程标题、**调用骨架** | 0a |
| **② 本站定向** | 本站产出与指令、本站的门、本站 Skill、上游清单、台账骨架 | 1 级 |
| **③ 当下状态** | 当前位置、阻塞清单、本次会话的用户指示 | 0b |

**调用骨架在第 ① 段，这一格不能漏。** 执行者看不到入口 Skill 的正文，而「执行」这一节已经
从站 Skill 里搬走了（§5）—— 两边都没有，执行者就是一个不知道自己该调「进」的进程。
它放在第 ① 段而不是第 ② 段，因为它跨站恒定，正好落在可缓存的那一段里。

没有简报时（用户直接调用某一站），替代品是控制面信封里的「下一步可以做什么」——
这也是 §3.4 那条「站 Skill 必须能自己定向」在实现上成立的方式。

**执行者按方案分类型，不按站分。** 六个站若是六种执行者，就有六个不同的系统提示，
互相之间零共享。站级写入范围来自方案作用域的投影（主文档《写入范围的权威》），
同一方案的各站拿到的是同一份，所以它们是同一种执行者、共享同一段前缀。

### 3.6 不是每一站都隔离

判据在主文档《人的介入点》：**人的介入点是这一站的主体，还是它的收尾？**

| 站 | 隔离 | 理由 |
| --- | --- | --- |
| **propose** | **否** | 主体就是把模糊想法收敛成一个有边界的目标 —— 那是和用户来回 |
| **clarify** | **否** | 本质就是问人 |
| **design** | **是** | 调查密集、产出明确；被丢掉的调查过程正是最该丢的 |
| **check** | **是** | 输入是几份已经写好的文档，产出是台账 |
| **apply** | **是（两层）** | 每个工作包本身就是封闭的：自有写入路径、自有验证命令。协调层也该隔离 —— 它今天在累积每一个包的全部往返 |
| **verify** | **是** | 跑门、写保证说明，输入明确 |

**可隔离不等于不需要人。** `verify` 末尾要一个验证收据的签署，`apply` 每个包末尾要一次集成
确认 —— 这两站的隔离执行者**必然以「需要人」出站至少一次**，由入口拿到主会话去问。
把「收尾要人」当成「不能隔离」，会白丢掉这两站最该丢的那部分累积。

不对称是刻意的。强行让每一站都一样，只会让前两站变得做不成。

### 3.7 执行者回来报什么

回报的纪律比隔离本身更重要 —— 做错了，隔离掉的东西会原样搬回来。

> **只报状态，不报过程。** 三种，此外没有第四种。

| 回报 | 含义 | 入口怎么办 |
| --- | --- | --- |
| **完成** | 这一站的产出与台账都写了 | 重新「读」，以控制面为准 |
| **卡住** | 报出阻塞 token 本身 | 重新「读」，看控制面给的补救 |
| **需要人** | 报出要问什么 | 回到主会话，问 |

**入口的真相来源永远是控制面，不是执行者的回报**（`一次调用一个进程`）。
回报只用来决定下一步做什么，不用来了解发生了什么。

### 3.8 降级

宿主不具备隔离能力时，站 Skill 就在主会话里加载并执行。**行为完全一样，只是不省。**

隔离是一项优化，不是一条语义。任何让「不支持隔离就跑不通」的设计都是错的 ——
产出、台账、证据、状态机在两种模式下逐字节相同。

## 4. 本地化区

定义、写权限与升级方式在主文档《本地化区》。这一层只说它长什么样、装什么：

- **每个站 Skill 里都有一块**，用标记划出来，不是独立文件 —— 和「混装文档」同源，
  标记划出的那一段按一种规矩读，其余按另一种。空着也是正常的。
- **装的是这个项目希望这一站怎么做**：本项目的写作约定、领域词汇、
  一句「我们这里的设计文档必须提到容量影响」。
- **只能加不能减这条不写死，这个扩展点迟早会被当成开关用** —— 用一段散文把一道门说没。
  执法的永远是门、台账、审批、权限策略；本地化区在它们之外，不在它们之上。

## 5. 一个站 Skill 装什么：四节

| 节 | 装什么 | 判据 |
| --- | --- | --- |
| **① 判断** | 这一站唯一不可替代的东西：控制面能告诉你欠什么，**不能替你决定什么算好** | 「如果这句话错了，谁会先发现？」答案是「实跑」的，才是判断 |
| **② 边界** | 能写哪些路径，**以及相邻但明确不能碰的哪些** | 把相邻的东西显式排除，读者就不需要靠推理找边界 |
| **③ 停下** | 什么条件必须停、停下之后交给谁 | 只写条件与去向，不写「上次是怎么撞上的」 |
| **④ 本地化区** | 项目自己的补充（§4） | 空着也是正常的 |

**第 ② 节是提示，不是执法**（主文档《写入范围的权威》）。

站 Skill 里常见、但装不进这四节的内容，各有归宿 —— 不是压缩，是搬家：

| 内容 | 去向 |
| --- | --- |
| **执行**（编号步骤） | 骨架是全局一致的 → **收进入口 Skill，只写一次**，并由简报第 ① 段带给执行者（§3.5） |
| **不变量**（「控制面会返回什么」） | **切片自带** |
| **证据**（对照完成判据报告） | **切片自带** |
| **陷阱**（事故记忆） | **迁往诊断码字典** —— 按码组织，撞上才看到；那些坑是产品的坑，不是某个项目的 |
| **台账字段规格** | **消失**。台账只有一个形状（`台账一个形状`），骨架由控制面起草并带来 |

设计不是「决定删掉它们」，是**让它们没有地方可待**。

## 6. 不写什么

七条，每一条背后都是一次真实的失败。

**① 不写与便利作对的禁令。**
「不要打开那个文件」这类句子，在实跑里输过很多次 —— 文件照开，文档照样重开二十多次。
**去补控制面，让诱因消失**（§1）。

**② 不写「空是不是故障」的辩解，直接说空是答案。**
一站什么都不欠时，实跑会去核实「为什么我什么都不欠」——
最贵的一次用十几条命令逆向编译后的工具，几十 KB 进上下文，此后几十轮重读，
该站账单是对照组的 2.6 倍。**空是配置，不需要核实。**

**③ 不制造孤名。**
控制面那边有 `名字不单飞`，但 Skill 自己也不许写下一个读者无处可查的名字。
一个没有解释的名字会被拿到最贵的地方去问。

**④ 不复制控制面或流程定义能陈述的事实。**
手抄的快照会静默漂移：改一处定义它就错了，**而且没有任何测试会红**。

**⑤ 不把事故记忆写进正文。**
每次进入都付费，而真撞上时，正文里只有作者当时记下的那一条措辞 ——
诊断码字典里有同一个码的**全部**变体，那才是撞上时该去的地方。

**⑥ 不按流程名字分支。**
「走 A 流程时……走 B 流程时……」这种写法，会让项目新增的自定义流程被**静默**处理错。
按控制面报的事实分支，不按名字。

**⑦ 不引用别的 Skill 的内部步骤。**
步骤是私有的，只有站的边界是公开的。

## 7. 本层的不变量

主文档《不变量》之外，这一层自己的：

| 名字 | 断言 |
| --- | --- |
| `Skill 只判控制面判不了的` | 控制面能陈述的，Skill 说「按它执行」。这是 Skill 存在的全部理由，也是它唯一的边界。 |
| `禁令先当缺口审` | Skill 的厚度与控制面的完整度成反比。一条禁令先当作控制面的缺口来审。 |
| `路由表不进正文` | 路由表来自流程定义，不在任何 Skill 的正文里。 |
| `交接不是继承` | 执行者从零开始；开局时简报就是它知道的一切；继承父上下文的派生方式与隔离互斥。 |
| `预加载定向不预加载材料` | 入口一旦开始预取正文，它自己就成了新的累积点。 |
| `站 Skill 能自己定向` | 预加载是优化，不是它的输入契约 —— 否则逐站单独调用的用法就断了。 |
| `只报状态不报过程` | 执行者回报三种状态；入口的真相来源是控制面。 |
| `隔离是优化不是语义` | 不具备隔离能力的宿主上，产出逐字节相同。 |
| `四节` | 一个站 Skill 只有四节。装不进这四节的内容，说明它属于别的层。 |
