# XForge 命令行：概念与架构

> 共同概念、对象与不变量在 [概念与架构](concepts-and-architecture.md)。
> 这份只讲**命令行这一层**：由哪几个动词构成，每个管什么、不管什么、凭什么不能互相冒充。
> 不含参数表、不含签名、不含迁移方案 —— 那些是设计方案，这份是设计**依据**。
>
> 主文档持有的东西这里不复述，只引用名字。看到 `写权限二分` 这样的名字，去主文档《不变量》。

---

## 0. 这份回答什么

三个问题：

1. 命令行到底有几件事要做 —— 不是「有几个命令」，是**有几种在性质上不同的操作**；
2. 一个 Agent 走完一个 Stage，要按什么顺序调用它们；
3. 每次调用应该回多少话。

第三个问题和前两个同等重要，理由是 `上下文成本一等约束`。主文档《上下文成本》定了裁剪规则，
这一层的事是**把哪些规则绑在哪个动词上**。

---

## 1. 五个动词

命令行上有且只有五种在性质上不同的操作。

### 1.1 读 —— 我在哪，欠什么，什么挡着

回答位置问题。

- **不写盘。** 同一棵树读多少次答案都一样。
- 它给的「什么挡着」是**算出来的，不是跑出来的**：读已经在盘上的证据与台账，与当前内容修订比对，
  得出阻塞清单。这个过程不执行任何项目命令，因此廉价、随时可调。
- 它承担**起草**（主文档《起草》）的一个挂载点：本站台账的机器已知部分由它渲染，断言字段留空，
  **在回复里返回，不落盘** —— 「读不写盘」没有例外。

**阻塞清单非空是正常状态**，不是故障。一个 Change 大部分时间都是被挡着的，那正是流程在起作用。

读有第二种形式：**点名取材料**。第 2 级的一切（文档正文、门输出、基线条目、章程正文、receipt 链）
只从这里取，Agent 不开文件 —— 这是主文档《能让控制面操作的就别开文件》在命令面上的落点。
它与位置问题共用一个动词，因为性质相同：不写盘、随时可调、答案只随树变。

### 1.2 验 —— 这份记录合法吗

回答完整性问题。它和「读」最容易混，但它们的失败含义相反：

- **读** 说「你还不能走」—— 正常
- **验** 说「有东西坏了」—— 异常

它检查的是**记录本身**：文件格式是否合法、引用是否悬空、receipt 链是否连续、摘要是否自洽、
署名与审计事件是否对得上（主文档《署名出现两次》）、哪些资源被声明了却没人用。

**铁律：验不写盘，也不执行任何项目命令。** 这条铁律是它的全部价值 ——
它必须是那个「任何时候调用都安全、都便宜」的动词。一旦允许它顺手跑一遍测试，
Agent 就不敢随便调它了，而那正是它该被随便调的。

**一个顺利的 Change 从头走到尾不需要调用它。** 这是设计意图，不是遗漏。
它的两种用法都在流程之外：**记录坏了的时候由人来定位**，以及**卫生检查由人或 CI 主动跑**
（「声明了却没人用」属于后者）。这两种都不是 Agent 在某一站要做的事。

### 1.3 产 —— 跑一次，把结果刻下来

执行并记录。**这是唯一会执行外部命令的动词。**

- 跑门，产出门的运行记录
- 跑工作包声明的验证命令，产出各自的记录

**产出的东西 Agent 不得手写**（`写权限二分`）。

它还承担一件容易被忽略的事：**受理那些由门把关的台账**（主文档《受理》）。
门在跑的时候读台账、判它、把判定写进自己的运行记录 ——
所以「这份台账被接受了」发生在门跑的那一刻，不需要任何额外的调用。

三条性质要一起记住：

1. **贵。** 一个大计划就是几十条外部命令、几分钟。这是整个命令行里唯一昂贵的动词，
   所以它必须能被窄化（只跑某一道门、只跑某一站的门）。
2. **有副作用。** 它写文件。所以它不能和「验」共用一个名字 —— 那会让一个本该安全的调用变得不安全。
3. **写失败必须能回退**（`写必须能回退`）。

**不产出成功报告，只产出记录。** 跑完之后回一句「过了」或者「哪一条没过、退出码多少、记录在哪」，
而不是把命令的全部输出回传 —— 那份输出已经逐字在盘上了。

### 1.4 证 —— 谁，说了什么

登记一个**必须当场记进审计链**的断言。

它的边界由 `有门能判的不走证` 定死，具体是哪五处由主文档《人的介入点》列出 —— 那张表同时是
「一站需不需要人到场」的判据，所以它属于主文档，不属于这里。

这一层要说的只有三件事：

**① 粒度由「谁在动」决定。** 证登记的全是人做的判断，所以它**一次一条** —— 那五处每处一次。
Agent 交的整份台账走的是门，不是证。

**② 它不写台账文件。** 证写的是审计事件；台账里的署名字段是 Agent 的一次转录，
两者由门核对（主文档《署名出现两次》）。**证的写入与台账的写入是两件事，落在两个地方。**

**③ 它在两台状态机上行为不同。** 工作包那台上，证默认捎带那一格的移动；
Stage 那台上不捎带。为什么不一致、代价是什么，在主文档《两台状态机》。

这里只记一条命令面的后果：**捎带的作用域按状态机划，而且不止这一个动词** ——
「进」也一样（Stage 机上捎带产，工作包机上不捎带，§1.5）。
**每一处捎带都必须连着它的作用域一起写**，否则读者只能从动词名字去推，而推不出来。

### 1.5 进 —— 状态机走一格

唯一写 receipt 的动词（`receipt 成链`）。两台状态机、寻址方式与审批粒度都在主文档《两台状态机》与《实现方案》。

Stage 机上的「进」进入一站时，还把方案作用域投影成站级策略；工作包机上的派工把包的写入路径投影成包级策略
（主文档《写入范围的权威》）。两处都记下执行的工作目录，执法靠它找回这份策略。

**进之前默认先产 —— 只在 Stage 那台上。** 实测每个 Stage 都是「跑门 → 移动」连着做，
而分开时最常见的失败是忘了重跑、导致门的记录相对当前内容已经过期。所以「进」默认包含本站的「产」。

**工作包那台上不捎带。** 那里的「进」是派工与移动，不跑任何项目命令 ——
这条作用域必须明写，因为工作包那台上的「证」又捎带着「进」（§1.4 ③）：
**捎带是会串起来的，一条没写明作用域的捎带，会让人以为一次确认能跑起外部命令。**

这不是把两个动词合成一个（`捎带合调用不合记录`）：产写门的运行记录，进写 receipt，
「门过了」和「状态机动了」在磁盘上永远分得开。

它也是**起草**的第二个挂载点：派工的回复里直接带上交付记录的骨架 ——
执行身份是那一刻才铸出来的，骨架唯一缺的就是它。

### 1.6 这五个为什么不能互相并入

分开它们的不是「它们从不一起发生」—— 有捎带，一起发生是常态。是**各自对不同的东西负责**，
并且各自失败时说的是不同的话：

| | 它自己失败时在说什么 | 读者该做什么 |
| --- | --- | --- |
| **读** | 你还不能走 | 去写欠的东西 —— **正常** |
| **验** | 这份记录坏了 | 找人修 —— **异常** |
| **产** | 某道门没过 | 去读那道门的输出 |
| **证** | 这个身份不成立 | 换一个真实的署名 |
| **进** | 条件不满足 | 回到读，看阻塞清单 |

「它自己」是这张表的前提：一次「证」可能以「集成检查没过」告终，一次「进」可能以「某道门没过」告终。
`出错给出路` 要求诊断说的是真正失败的那一件，不是被调用的动词名。

#### 各自对什么负责

| | 对什么负责 | 并进别的动词，坏掉的是什么 |
| --- | --- | --- |
| **读** | 「我在哪」这个答案的正确性 | 并进任何写盘的动词，「问一下」就变成「动一下」—— 而它是唯一一个随时可问、问多少次答案都一样的动词 |
| **验** | 「这份记录没坏」这个判断 | 并进读，「你还不能走」和「有东西坏了」就分不开，而这两件事一个正常一个异常；并进产，它变贵而没人敢调，可它的全部价值就是随便调 |
| **产** | 外部命令跑过了、结果逐字在盘上 | 并进进，门就只在状态机动的时候才跑得起来 —— 而一道门必须能被单独重跑 |
| **证** | 一个人说过这句话 | 并进任何机器动词，「有人确认过」就退化成一句话（`写权限二分`） |
| **进** | 状态机位置与链的完整性 | 并进产，一次跑门就等于一次移动，跑门变成不可试探的动作 |

**五种责任，五个归属，没有一个能被另一个承担。** 这是可检验的：第三列每一格都是一个
具体的、可以指着说「这就是那个坏掉的东西」的后果，而不是一句「它们不一样」。

## 2. 循环之外的三个面

不是每件事都在 Change 的循环里。以下三类的**调用者不同**，所以不该和五动词平铺在一起。

### 2.1 装配 —— 让这个项目有一套 harness

调用者：人或 CI，一次性。作用对象是 harness 自己，不是任何 Change。

| | 做什么 |
| --- | --- |
| **初始化** | 从零建立治理目录树；在已初始化的项目上重入即幂等对账 |
| **同步** | 把脚手架的当前状态投影到各 Agent 平台的原生位置；自己判断处在「首次 / 只有本地改动 / 结构变了」哪一种，据此决定扫描深度与作用域 |
| **升级** | 取新版脚手架 |

**升级是三段式的，这一点不能压扁：**

```
暂存 ── 快照当前受管树（这是回滚点）+ 铺开新版 + 逐文件分类
  │
  └─→ 人或 Agent 合并 ←── 在途期间磁盘上有一个刻意可见的哨兵
        │
        ├─→ 完成：推进版本锚点，记录「合并实际保留了什么」（不假设全盘采纳）
        └─→ 回滚：从快照整树恢复
```

中间那一步是人的判断，不是命令的一个阶段。包里多了一个 Skill 不等于决定要跑它 ——
升级把文件带进来，选不选是项目的决定。所以在途状态必须在命令面上可见，
而不是藏在一个看起来是原子操作的命令背后。

**逐文件分类有一个例外**：带本地化区的文件做移植，不做三方合并（主文档《本地化区》）。
升级事务必须认识那个标记，否则每次升级都会在同一个文件上冲突一次。

**工具自身的升级不在这里。** 二进制由包管理器装，命令行不自我更新。
需要区分的是两件事：**包管理器装的是二进制，Manifest 记的是这个项目认定自己跑哪个版本的锚点。**
后者是治理决定，不是 shell 里的临时决定。

### 2.2 执法 —— 在工具调用发生的那一刻做决策

调用者：宿主平台进程，不是 Agent，也不是人。

这是**唯一的运行期动作**，其余全部发生在工作流平面。它由宿主在每次工具调用前唤起，
读一份宿主格式的载荷，回一个宿主格式的决策。它从载荷里只取工具名、参数与工作目录 ——
工作目录用来找回在途的投影策略（主文档《写入范围的权威》），不依赖任何宿主特有的身份字段。

它有三条与其它所有命令都不同的性质：

1. **它不返回统一信封**，而是返回宿主要求的形状 —— 决策通道上出现一个信封，
   会被读成「没有意见」，也就是放行一切。
2. **它读不了策略就拒绝**（`失败朝安全`）。一个无法为自己所依据的策略集背书的执法者，
   不许允许任何事。
3. **拒绝必须留一条出路**（`拒绝要留出路`），而且那条出路要**按动词开，不按二进制开**。

第三条值得展开，因为它最容易开得太宽。治理读不出来时每次调用都被拒是对的，
但那条「去修好那个文件」的建议本身也是一次工具调用。所以放行的是：

| 放行 | 为什么 |
| --- | --- |
| **读文件** | 改变不了任何东西 |
| **元信息**（帮助、版本、诊断码字典） | 不碰项目状态 |
| **读**（五动词之一） | 不写盘，而且它正是那条出路要读的东西 |
| **装配的对账** | 修好治理文件本身，正是这个拒绝要求的动作 |

**产、证、进一律拒绝。** 「跑 xforge」不能整个放行 —— 那三个动词恰好是在治理无法执法时
最不该畅通的：状态机推进、证据写入、审批登记。**把出路开成一个二进制，等于没有拒绝。**

### 2.3 元信息 —— 不需要项目就能回答

帮助、版本、诊断码字典。诊断码字典之所以在这里而不在「读」里：
一个人在不是 XForge 项目的目录里撞见一个错误码，仍然需要能查到它是什么意思。

它同时是**事故记忆的归宿**：那些「上次是怎么撞上的」按码组织放在这里，撞上才看到，
而不是常驻在某份 Skill 的正文里每次进入都付费。

## 3. 怎么用

### 3.1 一个 Stage 的循环

```
① 读              我在哪、这一站欠什么、要读哪几个文件、什么挡着（含台账草稿、本站 Skill）
      │
      ├── Agent 按 Skill 写 Artifact / 写台账      ← 命令行在这一段完全不参与
      │
② 证（若有）      这一站若有「没有门能判」的断言，登记它
      │
③ 进              默认捎带跑本站的门 —— 门顺带受理了这一站写下的台账 —— 然后移动
```

**三次调用。** 这个数字之所以成立，全靠 `有门能判的不走证`：台账由门受理，不额外走证。
若每份台账都要一次登记，一个欠两份台账的站就是五次。

两处例外，都是真实工作量而不是开销：

- **人的介入点落在这一站**就多一次（主文档《人的介入点》那五处）。
- **Apply 站与包数线性相关**：每个包是一次派工、一次交付登记、一次集成确认、
  必要时一次评审确认。

> **这三次是命令行付的账，不是 Agent 会话里的总调用数。** Skill 那一层的入口还会为
> 「拿到真相」再读一次 —— 那是那一层的事，记在那一层。

被挡住时不需要额外的命令：第 ① 步已经给了阻塞清单。清单里的每一项都对应一个动词：

| 挡住的原因 | 该做什么 |
| --- | --- |
| 某个 Artifact 没写 | 写它（不是命令） |
| 某份台账没写 | 写它（不是命令）—— 下一次「进」跑门时受理 |
| 某道门没跑过 / 没过 / 记录过期了 | **产** |
| 某个审批还差人 | **证**（人来做） |
| 某个工作包还没交付 | 那台状态机上的 **进** 与 **证** |
| receipt 链不连续、格式非法 | **验** 去定位，然后人来决定 |

### 3.2 并行交付时

工作包那台状态机由 Skill 驱动，命令行只提供四个接触点：
**进**（派工，铸出执行身份）、**起草**（给交付记录打底）、
**证**（集成确认、评审确认）、**产**（跑各包声明的验证命令）。

**每个包四次调用**：派工（进）、交付登记（进，入参是执行者写好的交付记录）、
集成确认（证，捎带进）、必要时评审确认（证，捎带进）。捎带的作用域见 §1.4 ③。

交付记录本身是台账，工具不写。评审结论是只读评审者的返回，必须逐字转录，
放在一个不会被当成交付记录解析的位置。

## 4. 一个信封

所有命令返回同一个结构：**成功与否、结果、诊断、改动了哪些文件、下一步可以做什么**。
`--text` 只改呈现，不改语义、不改退出码。

唯一的例外是执法 —— 它必须说宿主的语言（§2.2）。

裁剪规则本身在主文档《裁剪八条》。这一层要绑的是**哪条规则对哪个动词最要命**：

| 动词 | 最要命的那条 |
| --- | --- |
| 读 | **`名字不单飞`** —— 它是唯一大量吐 id 的动词 |
| 验 | **`出错给出路`** —— 它只在异常时被调用，回复全是诊断 |
| 产 | **`大块给指针`** —— 通过的门给结论，失败的门才给正文 |
| 证 | **`正常就说正常`** —— 一次登记成功没有别的可说 |
| 进 | **`切片自称完整`** —— 它捎带的按站材料是下一段工作的全部输入 |

## 5. 本层的非目标与开放问题

**不做的：让命令行「多做一点」。** 理由是主文档《定位》—— 一个会替你做判断的控制平面，
它记录下来的东西就不再能作为证据。

> **开放问题一：「验」能不能判定 Skill 覆盖了本站要求。**
> 今天这条被写成验的一项检查，但按 `不读散文的意思` 它不可实现：Skill 正文归 Agent，
> 控制面只能验骨架，而骨架（四节）对所有站都一样，标题匹配永远区分不出覆盖与不覆盖。

> **开放问题二：卫生检查谁来跑。**
> §1.2 把「声明了却没人用」这类检查放在流程之外，由人或 CI 主动跑 —— 但没说多久跑一次、
> 红了算不算阻塞、谁看。它现在是一项没有触发条件的检查，而没有触发条件的检查等于没有。

> **开放问题三：拆除。**
> 从声明里去掉一个平台再同步，已经能清掉它的产物 —— 这覆盖了绝大多数场景。
> 剩下的是「我不再使用 XForge 了，全部移除」，它是破坏性的，不应该藏在日常命令的一个开关后面。
> 倾向是把它作为一个需要显式确认的独立动作。
